# Project and Chat Inventory Exports

ChatGPT Exporter can export lightweight inventories of Projects and chats without exporting full conversation content.

## Purpose

The inventory exports provide stable lookup data for downstream tooling, including the existing Project-map workflow used by the ChatGPT-to-Obsidian importer.

The inventory exporter is available from **Export Project / Chat Lists** in the exporter menu.

## Supported output formats

The inventory exporter deliberately supports four formats only:

- JSON
- TXT
- HTML
- Markdown

CSV is not generated by this feature.

## Project list

Project exports contain these fields, in this order:

| Field | Meaning |
| --- | --- |
| URL | A direct ChatGPT Project URL generated from the Project token. |
| Token | The Project URL token. An existing `GizmoID-Slug` token is preserved; when only a bare Gizmo ID is available, the exporter appends a deterministic slug. |
| GizmoID | The stable `g-p-...` Project identifier used to associate conversations with Projects. |
| Slug | The Project URL slug. An existing token suffix is preserved; otherwise it is generated deterministically from the current Project name. |
| Actual Project Name | The current Project display name returned by ChatGPT. |

The existing `URL, Token, GizmoID, Slug` Project-map contract is therefore preserved, with `Actual Project Name` appended. Keeping the URL identity separate from the current display name also means a Project rename does not silently rewrite an existing token/slug when ChatGPT supplies the historical token.

## Chat list

Chat exports contain these fields, in this order:

| Field | Meaning |
| --- | --- |
| URL | Direct `https://chatgpt.com/c/<conversation-id>` link. |
| Token | The conversation identifier used in the URL. |
| Slug | Deterministic slug generated from the actual chat title. |
| Actual Chat Name | The current chat title returned by ChatGPT or present in an imported conversation file. |
| Project Name | The matching Project display name when the conversation has a known Project Gizmo ID; otherwise blank. |

## Filters

The inventory dialog follows the current bulk-export filter model:

- source: ChatGPT API or an official `conversations.json` export;
- Project: all conversations, not in a Project, or one named Project;
- date field: created or last updated;
- from/to date range;
- wildcard-aware search using `*` and `?`.

For chat inventories, search applies to chat titles.

For Project inventories, search applies to Project names/slugs. Date filtering retains Projects that have at least one matching conversation in the loaded data. If no date filter is active, the Project inventory can include Projects that currently have no conversations.

The normal bulk-export conversation limit still bounds API conversation discovery. Project metadata itself is fetched from the Projects endpoint and is not truncated by that conversation limit.

## Project membership

When conversations are loaded from a specific Project endpoint, the inventory exporter retains the endpoint's Project identity even if an individual conversation row omits `gizmo_id`. This allows `Project Name` to remain reliable without modifying the conversation itself.

For the main conversation feed, known Project Gizmo IDs are normalised before identifying conversations that are not in a Project. Custom GPT conversations remain non-Project chats unless their Gizmo ID matches a known Project.

## Slug generation

When a stable slug is not already present in a Project token, or when a chat slug is needed, slugs are generated deterministically:

1. Unicode text is normalised and combining accents are removed.
2. Apostrophes are removed.
3. Text is converted to lower case.
4. Non-alphanumeric runs become a single hyphen.
5. Leading and trailing hyphens are removed.

Example:

`GitHub - ChatGPT Exporter` → `github-chatgpt-exporter`

## Limitations

ChatGPT's internal API is not a documented public contract. Project and conversation fields can change between ChatGPT versions. The exporter therefore treats optional identifiers defensively and leaves `Project Name` blank when a conversation cannot be matched reliably to a known Project.

For local `conversations.json` input, Project filtering/name resolution depends on the exported conversation records containing a usable `gizmo_id`. If that field is absent, the exporter does not manufacture Project membership.

## Validation

The repository includes deterministic validation covering:

- Project token, Gizmo ID and slug derivation;
- Project rename stability when an existing token suffix is available;
- duplicate suppression;
- chat URL/token/slug generation;
- Project-name lookup and unknown Project handling;
- JSON, TXT, HTML and Markdown serialisation;
- escaping of HTML and Markdown-sensitive content.
